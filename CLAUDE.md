# Footnote Daily (campus-publication), v3

Research-first guides for students, parents and alumni of Cornell University and Ithaca. Owner specs: `docs/v3/spec.md` (2026-11-08, wins where it conflicts) over `docs/v2/spec.md` (files, lint, render, images, monetization, deploy). Style: `docs/v2/style.md` (stand-in until the owner's `footnote-style-guide.md` arrives). Quality bar: `docs/v2/exemplar.md`. Status: `STATE.md`, overwritten, under 60 lines. This file and STATE.md describe only what exists and runs. Nothing runs on a schedule; Ajay starts every step.

## The v3 pipeline (scripts/v3/, one topic at a time; topics and scopes in `topics.yml`)
1. `research.sh <topic>`: five lanes (official, market, voice, competition, analysis) write `intel/<topic>/raw/<lane>.md`; a lane is complete only when its file ends with a `## Lane complete` line, else the next run continues the same file. `--deepen` extends thin lanes.
2. `brief.sh <topic>`: one opus synthesis session writes `intel/<topic>/brief.md` (11 sections, 15k to 40k words), an expand pass if short, then one sonnet fact-check session per lane (findings in `brief-check.md`). `reverify.sh <topic>` reruns the checks.
3. `readers.sh <topic>`: `intel/<topic>/readers.md`, at least 10 reader types with the six fields.
4. `plan.sh <topic>`: `intel/<topic>/plan.md` (pillar, spokes, reader guides, tools, datasets, start pages) and proposed queue rows; the approval copy is `reports/plan-<topic>.md`. Ajay approves with `plan.sh <topic> --approve`.
5. `write.sh <topic>`: one opus session per page writes from the brief, runs the seven editing passes and the 3-reader test itself; two drafts and a cold pick for pillars; tools and datasets as pages; `--fix` for the one revision. 6. `check.sh <topic>`: sonnet checks only facts not in the brief plus our own math, fixes in place. 7. `bash scripts/v2/publish.sh`: lint (v3 publish requirements), render, deploy.
- `run.sh <topic>`: does the steps above in order, stopping once for the plan approval, then loops write, fix, check, publish with a REPORT every 10 pages. `requeue_v2.py <topic>` queues published v2 pages for a v3 rewrite. `learn.sh`: the on-demand learn run (`reports/learn-<date>.md`, proposals in `reports/lessons.md`). Stop anything cleanly: `scripts/v2/stop.sh`.

## v2 pieces still in use (scripts/v2/)
`find_demand.sh` (queue rows from real questions), `publish.sh`, `lint.py`, `render_site.py` (At a glance, reader blocks, tools, datasets, start pages, feedback box), `find_images.py` (licensed, relevant photos: CC0, public domain, CC BY, CC BY-SA only; the article's school, town and subject from `config/schools.yml` and its frontmatter; `--audit` writes `reports/photo-audit.md`; ledger `content/images/credits.yml`), `indexnow.py` (after each deploy, submits new and changed sitemap URLs; log `reports/indexnow.log`; crawler allow and disallow lists and the key file in `config/crawlers.yml`, which `render_site.py` turns into the production robots.txt), `lib/sessions.py` (parallel `claude -p`, usage-limit pause, STOP), `lib/queue.py` (`queue/queue.csv`; `dedupe`), `export_corpus.py`. `write.sh`, `review.sh` and `run_continuous.sh` are the stopped v2 writers.

## Layout
`content/` (articles by topic dir, tools, datasets, start pages, pages, reviews, checks, edits, images), `queue/queue.csv`, `intel/<topic>/`, `corpus/<host>/<path>.txt` (2,522 crawled pages), `reports/`, `config/monetization.yml`, `data/questions/`, `worker/campus_worker/render/` (templates, static assets, `figures.py`; the only worker code left). `archive/v1/` holds everything else from v1; nothing runs from it. Map: `docs/v3/repo-map.md`. `site/`: the Astro site templates (14 templates, shared components, `site/README.md`); since 2026-11-08 `scripts/deploy_netlify.sh` builds it and deploys `site/dist` to footnote-daily.netlify.app (the Jinja render in `build/site` stays for lint and local preview; `CAMPUS_DEPLOY_LEGACY=1` restores the old deploy). Judgment calls: `DECISIONS.md`.

## Rules
Every hard fact links to its source; student experience is paraphrased and attributed; never invent facts, numbers, quotes or people. Respect robots and site terms; no logins; no bulk scraping; photos only with a reuse license or written permission, credited and relevant. Quality fixes go in prompts, the style guide, the exemplar and the briefs, never in code rules; no new gates, scores or databases. Secrets live only in `worker/.env`, never read by Claude. Commit per step; never force-push.

## Running
Python `worker/.venv` (pyyaml, markdown, jinja2, httpx, Pillow). Deploy: `bash scripts/deploy_netlify.sh`. Logs: `build/runs/v2/`.
