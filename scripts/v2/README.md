# Running the v2 pipeline (docs/v2/spec.md)

1. Find demand: `scripts/v2/find_demand.sh housing` (or `all`, or any of housing getting-around academics money daily-life careers parents alumni). One session per topic writes `queue/proposed/<topic>-<ts>.csv`; the script merges it into `queue/queue.csv` (gap and weak rows become `proposed`, owned rows `owned`). Approve rows by editing the status column, with `worker/.venv/bin/python scripts/v2/lib/queue.py approve --ids q-housing-0001,q-housing-0002`, or run the step with `--auto-approve`.
2. Write: `scripts/v2/write.sh --workers 4` (add `--model opus` when the plan allows, `--limit 10` for a pilot, `--ids a,b` for specific rows). One session per approved row; the article lands in `content/articles/<topic>/<slug>.md` and the row becomes `written` (or returns to `approved` with the reason in the log). Photos: `scripts/v2/find_images.py` finds licensed candidates before the session (`content/images/candidates/<id>.json`); the ones the writer picks are downloaded to `content/images/<slug>/<n>.webp` and logged in `content/images/credits.yml` right after it.
3. Review: `scripts/v2/review.sh --workers 4`. A fresh session per written article writes `content/reviews/<slug>.json`. pass keeps the row `written` for publishing; fix sets `fix`, then run `scripts/v2/write.sh --fix` and `scripts/v2/review.sh` once more (a second fix verdict rejects); reject sets `rejected`.
4. Publish: `scripts/v2/publish.sh` (`--deploy-every 10`, `--no-deploy`, `--render`). Lints every article with a passing review, marks the clean ones `published`, renders the published rows' articles (a copy under `build/publish/articles/`) to `build/site/` with `scripts/v2/render_site.py` and deploys with `scripts/deploy_netlify.sh`.

Stop any step cleanly with `scripts/v2/stop.sh` (sessions in flight finish; the next run clears the flag). A usage limit pauses the workers and a one-turn haiku probe resumes them (`worker/.venv/bin/python scripts/v2/lib/sessions.py probe` runs it by hand).
Logs: `build/runs/v2/<step>-<timestamp>.log`; every prompt sent is in `build/runs/v2/prompts/`, every session result in `build/runs/v2/sessions/`.
Lint one article by hand: `worker/.venv/bin/python scripts/v2/lint.py content/articles/<topic>/<slug>.md` (`--no-network` skips the URL and copied-text checks).
Queue by hand: `worker/.venv/bin/python scripts/v2/lib/queue.py list --status approved`, `show ID`, `set-status ID STATUS [--force]`, `merge FILE.csv`.
Prompts the sessions get: `scripts/v2/prompts/{demand,write,review}.md`. Quality fixes go there, in `docs/v2/style.md` and `docs/v2/exemplar.md`, never into code rules.
