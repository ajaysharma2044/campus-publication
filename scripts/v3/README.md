# Running the v3 pipeline (docs/v3/spec.md; v2 still owns files, lint, render, images and deploy)

One topic at a time, in this order; `<topic>` is a slug from `scripts/v3/topics.yml` (`off-campus-housing`, `getting-around`, `money`, ...); its articles live under `content/articles/<dir>/`.

1. Research: `scripts/v3/research.sh <topic> [--lanes A,B,C,D,E] [--workers 5] [--model sonnet]`. Five lanes (official, market, voice, competition, analysis) write raw, sourced, dated notes to `intel/<topic>/raw/<lane>*.md` plus `raw/demand-questions.md` (the topic's queue rows). Best started overnight; several topics may run at once.
2. Brief: `scripts/v3/brief.sh <topic> [--model opus] [--max-turns 200] [--check-model sonnet] [--skip-check] [--resume]`. One opus session merges every raw file into `intel/<topic>/brief.md`: 11 numbered sections (`## 1. The topic in one page` to `## 11. Change log`), 15,000 to 40,000 words, every fact row with Source URL, Applies to and Checked; it writes the skeleton first and fills it with Edit. Under 15,000 words, one more "expand" session adds depth from the lanes. Then one sonnet fact-check session per lane (five in parallel) opens the sources, fixes the brief in place and appends its findings to `intel/<topic>/brief-check.md`. The script prints the word count, each section's presence and size and the check totals; `--resume` keeps an existing brief (only expand and check), otherwise the old brief is moved to `build/runs/v2/brief/`.
3. Readers: `scripts/v3/readers.sh <topic> [--model opus] [--min-readers 10]`. One session reads the brief and the demand rows and writes `intel/<topic>/readers.md`: one `## Reader: <name>` section per reader type with a `Key:` line and the six fields (Situation, Questions in their words, Decisions with numbers, Timeline, Mistakes and cost, Brief facts that matter). Prints the count; fewer than 10 is a failure.
4. Plan: `scripts/v3/plan.sh <topic> [--model opus] [--limit-spokes 30]`. One session writes `intel/<topic>/plan.md`: a table `kind | slug | title | question | primary_query | type | readers | brief_sections | notes` with exactly one pillar, 10 to 30 spokes, reader guides, tools, datasets, start-here paths and rewrites of existing articles. The script adds a row per planned page to `queue/queue.csv` (id `q-<dir>-NNNN`, question = the title, verdict `plan`, angle `kind=...; slug=...; readers=...; type=...`, status `proposed`), skipping slugs already queued or built, and prints the summary Ajay reads.
5. Approve: Ajay reads `intel/<topic>/plan.md` (about ten minutes), fixes rows by hand if needed, then `scripts/v3/plan.sh <topic> --approve` flips the topic's proposed plan rows to `approved` without a new session.
6. Write and edit: `scripts/v3/write.sh` (one opus session per approved plan row writes and edits the article from the brief, the reader map and the plan row; every 10th article gets a cold editor read). 7. Check: `scripts/v3/check.sh` (sonnet; only facts not in the brief, plus our own math; `content/checks/<slug>.json`). 8. Publish: `scripts/v2/publish.sh` (lint, render, deploy; `reports/to-read.md` for Ajay's spot check). Tools, datasets and start pages are built from their plan rows by their own steps; never run `scripts/v2/write.sh` on plan rows.

Every step: `--model` and `--workers` as flags, log in `build/runs/v2/<step>-<ts>.log`, prompts sent in `build/runs/v2/prompts/`, session results in `build/runs/v2/sessions/`; stop cleanly with `scripts/v2/stop.sh` (`.run/STOP`), and a usage limit pauses and resumes on its own (`scripts/v2/lib/sessions.py`).
Prompts: `scripts/v3/prompts/*.md`. Quality rules live there, in `docs/v2/style.md`, `docs/v2/exemplar.md` and the briefs; never in code.
Notes: `brief.py` lifts the Edit tool for its own sessions only (sessions.py disallows Edit for every v2 step), scoped to the intel folder; `plan.py` extends queue.py's topic list from `topics.yml` at run time (dining, transfer, health). The plan's question, brief_sections and notes columns stay in `plan.md`, where the writer reads them by slug.
Tests (no real sessions): point `CLAUDE_BIN` at a stub that writes the expected files and run each step with `--intel-dir <tmp>/intel` (and `plan.sh --queue <tmp>/queue.csv`).
