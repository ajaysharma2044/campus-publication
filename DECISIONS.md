# DECISIONS.md: Footnote Daily site templates (the Astro build in `site/`)

Judgment calls made while building the site template system on 2026-11-08, in the order they came up. Each entry says what was decided and why. Entries marked **OWNER** need Ajay's decision before the build goes further. The Python renderer (`scripts/v2/render_site.py`) and everything outside `site/`, `reports/templates/`, `reports/lighthouse/` and this file were left untouched.

1. **`design/reference-article.html` does not exist, so the owner's written design notes stand in for it.** The catch-up spec names `design/reference-article.html` as the visual source of truth for type, color, spacing and components. The file is not in the repository and was not found anywhere on this Mac. Every template was built from the owner's written description instead: Newsreader (headlines, logo, section titles, numerals) and Libre Franklin (body, interface), the twelve palette tokens (navy #0E1B33, navy-2 #26385E, navy-3 #B8C2D6, gold #D6A738, gold-ink #7E5F0B, highlight #FBE3A1, ink #16181D, text #2A2D33, muted #5E6573, rule #E2E4E8, surface #F4F5F7, link #1C4791), the masthead, school sub-nav, article, sidebar and footer anatomy, and the banned list (no inline styles, all-caps labels, tinted or bordered cards, pill highlights, gradients other than the marker stroke, shadows, emoji, gray placeholders). Deliverable 3's side-by-side of the pillar template against the reference could not be produced; the pillar screenshots stand alone. **OWNER:** supply the file. The first job once it arrives is a true comparison, and any difference in spacing or type sizes is then a stylesheet change in `site/src/styles/global.css` only.

2. **Branch and commits.** This checkout (`/Users/ajaysharma/Ads/campus-publication`) is on `main` and is shared with the catch-up session, which was committing its own work at the same time. Commits were made on `main` and contain only files under `site/`, `reports/templates/`, `reports/lighthouse/` and this file. Nothing was pushed or deployed.

3. **Astro 5.18 rather than the newest major.** Pinned to a major whose content-collection and build APIs are stable and well documented; nothing in the spec needs a newer feature. Node 22 and npm come from `~/.local/node/bin`; Playwright 1.56.1 is loaded from the repository's root `node_modules` (not duplicated under `site/`); Lighthouse 13.6 and Pagefind 1.6 are `site/` dev dependencies. Lighthouse runs on Playwright's Chrome for Testing build (`~/Library/Caches/ms-playwright/chromium-1248`) for a fixed browser version; the installed Google Chrome 156 was not re-tested after the fix below. (The first full runs timed out with no report, which I first blamed on Chrome; the cause was my runner starting Lighthouse with a blocking `spawnSync` in the same process as the static server it was measuring, so the server never answered. The runner now spawns asynchronously.)

4. **URL scheme.** `/{school}/{topic}/{slug}/` with the school slug `cornell` (site.config `schools[].slug`; the content id stays `cornell-university`), data pages at `/{school}/data/{slug}/`, cross-school guides at `/guides/{slug}/`, audience hubs at `/{school}/parents/`, `/transfer/`, `/alumni/`. The Jinja site publishes `/{topic}/{slug}/`. Internal links inside article bodies are rewritten to the new URLs at build time; a link to a page that is not on the Astro site becomes plain text (the renderer's own rule). **OWNER:** if the Astro build replaces the Jinja site, the old URLs need 301 redirects (a short Netlify `_redirects` file, not written because the replacement decision is open).

5. **Content-to-template mapping (`site/src/lib/model.ts`).** An explicit frontmatter `page_type` wins. Otherwise: `cross_school: true` → cross-school guide; a `data` block → data page; a `place` block → place review; a `comparison` block → comparison page; v3 `kind: pillar` → pillar; everything else by length, 1,200 words and up → pillar, under → quick answer (site.config `content.pillarMinWords`). The spec sizes pillars at 2,000 to 5,000 words and answers at 300 to 900; the 46 existing v2 guides all sit between 790 and 1,940, so 1,200 is the split that gives the long decision guides the full layout (32 pillars, 14 quick answers). The v2 `type` values `place` and `comparison` do not select the place or comparison templates: those v2 pages are roundups and decision guides without the structured blocks the templates require. **OWNER:** confirm the threshold or set `page_type` per page.

6. **Build failures (the spec's "build fails on").** In the model, before rendering: unknown `page_type` (schema enum; `hub` is reserved for generated hubs), missing title, meta, topic, updated, unknown school or topic, fewer than one source, fewer than five sources on a pillar or cross-school guide, a place page missing any fact of its category, a data page without columns and rows, a comparison with fewer than two items. After the build, `site/scripts/check-build.mjs` reads `dist/`: exactly one H1, no `style=` attribute, title, description, canonical, og:image, JSON-LD and a main landmark on every page, every internal link resolves, at least three outbound internal links from the main content (breadcrumbs and the shell excluded; styleguide pages exempt), and every child page listed on its topic hub, data index or `/guides/`. Any failure exits non-zero and fails `npm run build`.

7. **Which articles render.** All 46 files in `content/articles`. The Python renderer publishes only articles whose queue row is `published` (16 today); the Astro build ignores that gate by default so the templates can be reviewed on real pages (site.config `content.includeUnpublished: true`). **OWNER:** set it to false before any production deploy, which restores the queue gate.

8. **Bylines name no one.** No article carries an author. Every byline resolves to "Footnote Daily editors", an organization entry in site.config `authors` with its own page at `/authors/footnote-daily-editors/` describing the editorial process. The "Reviewed by" line appears only when frontmatter `reviewed_by` names a configured author. Article schema uses an Organization author; the author template emits Person + ProfilePage only for `kind: person`. Nothing was invented. **OWNER:** add real authors to site.config and `author:` to frontmatter when ready.

9. **"Most read" and the homepage lead need traffic data that does not exist.** Both read site.config lists (`mostRead`, `featured`). While those are empty the fallback is the longest pillar guides, and the sidebar block is labeled "Start here", not "Most read", so the page makes no claim it cannot back. **OWNER:** fill the lists or wire analytics.

10. **Homepage "Data and trackers" and the school hub's data section.** No data page exists yet, so the homepage omits the trackers row rather than show placeholder links, and the school hub says trackers are being compiled and links the data index.

11. **Audience hubs reuse the topic directories.** `parents`, `transfer` and `alumni` are topics in `content/articles` and audiences in the spec; the audience hub takes over those three URLs and groups guides from every topic by journey stage using keyword rules in site.config `audiences` (stage names from the spec's example, regexes written for the current titles). Leftover guides of that topic fall into "More guides". The rules are a stand-in for editorial curation.

12. **The short answer is the opening paragraph.** The house rule since v2 is that the first paragraph answers the question, so the template lifts it into the ShortAnswer block. Marker highlights: the first two `<strong>` runs in that paragraph become marker strokes, any further ones stay bold. The v2 guides use no bold there, so real pages show none today; the samples show them. **OWNER:** writers can mark the two key phrases bold in the opening paragraph.

13. **Figure blocks.** `cost_table` → FactsTable markup inline where the writer placed it; `steps` → Steps; `timeline` → a dated Timeline list in the same style. The v2 inline SVG charts (`figures.py`) are not reproduced; the Chart component serves data pages. A pillar may also carry a frontmatter `facts:` list, which renders the spec's FactsTable after the first ad. Figure YAML uses the renderer's lenient fallback (labels with colons are quoted and re-parsed), so all 45 blocks in the current articles render. `glance` → an "At a glance" note; `reader` → an open details block; `tool` → a one-line note (tools are not ported).

14. **Footnotes are derived from the sources list.** A body link whose URL matches a listed source gets a gold numbered marker linking to that entry; the entry's arrow links back to the first marker. The Sources list is the frontmatter list in its order, with host and access date.

15. **FAQ, related and contents extraction.** An H2 named FAQ, Frequently asked questions, Common questions or Related questions with H3 questions becomes the FAQ component and the FAQPage schema; a trailing "Related guides" list becomes related links; a writer's "What's in this guide" list is dropped in favor of the TOC component (three or more H2s).

16. **Ads.** One AdSlot with fixed reserved heights. Provider `none` (the default): empty reserved space in production builds, a dashed outline with the "Advertisement" label in dev builds. In-content ads: one after the short answer, then between H2 sections once about 700 words have passed, so an ad can never sit inside a list, table or step sequence. The sidebar 300x600 is sticky within the sidebar column on desktop and hidden below 980px; the mobile anchor renders only when a provider is configured. In-content units are 300x250 everywhere (336x280 does not fit a 375px screen); the homepage leaderboard is 728x90. The blank bands in the screenshots are these reserved spaces.

17. **Newsletter.** The form posts to site.config `newsletter.endpoint`, a placeholder (`/newsletter/subscribe/`) the link checker ignores. **OWNER:** the list provider's endpoint.

18. **Fonts.** Google Fonts' latin variable woff2 builds of Newsreader (v26, weight and optical-size axes) and Libre Franklin (v20), roman and italic, with the SIL Open Font License texts from the upstream repositories beside them in `site/public/fonts/`. Latin subset only. Two files preloaded; `font-display: swap`. The two Newsreader files were then narrowed with fontTools (`varLib.instancer`) to weight 400 to 700 and optical size 16 to 72, the ranges the stylesheet uses, keeping both axes so optical sizing still works: 132 and 147 KB became 88 and 98 KB, which took the pillar template's mobile LCP from 3.2 s to 2.6 s and its performance score from 93 to 97. Neither family declares a Reserved Font Name, so names are unchanged; `site/public/fonts/README.md` records the processing.

19. **Logo and marks.** The logo is live text ("Footnote Daily" in Newsreader 600 with a gold superscript 1). The favicon is a hand-written SVG; the PNGs (32, 180, 192, 512 and a 400px social avatar) and the default Open Graph card were rendered from the same mark with Playwright (`site/scripts/brand-assets.mjs`). Per-page Open Graph image: the lead photo when there is one, else the default card; no per-page generated cards.

20. **Photos.** `site/scripts/sync-images.mjs` (prebuild) turns `content/images/<slug>/*.webp` into 480, 800 and 1,200px AVIF and WebP variants under `site/public/images/` (gitignored, regenerated on every build) and records sizes for width/height attributes. Credits and licenses come from the article frontmatter. Lead photos and card photos are shown at 3:2 with object-fit cover so a portrait source does not fill the screen. The sample pages borrow one real licensed photo (Cornell University West Campus entrance, 颐园居 / Wikimedia, CC BY 4.0) with its real credit rather than a fake credit on a real image.

21. **Trust pages.** `content/pages` supplies about, editorial-policy (served at `/editorial-standards/`, the spec's name), corrections, contact and privacy. The spec's two missing pages, `/sources/` and `/advertise/`, were written in `site/src/content/pages-extra/` in the house style with `[OWNER: ...]` placeholders where a fact is the owner's. The `thanks` page and the feedback form belong to the Jinja renderer and are not ported (not in this spec).

22. **Search.** Pagefind builds a static index after the build; the search page renders results as GuideList rows with our Pagination (10 per page) from the Pagefind JS API, no Pagefind UI styles. Indexed: guides, hubs and trust pages; excluded: the homepage, author pages, the guides and authors indexes, and every noindex page. `/search/` and `/styleguide/` are noindex and disallowed in the production robots.txt.

23. **404.** Astro writes `dist/404.html`; Netlify serves it with a real 404 status, and the local preview server (`site/scripts/serve.mjs`) does the same. One school exists, so "the top 5 school hubs" is the Cornell hub with its first five topic hubs.

24. **Gold and contrast.** Gold (#D6A738) on white measures 2.1:1, below AA for text and for focus indicators. The gold numerals the spec asks for (TOC, steps, most read, sources) are CSS counters that duplicate real list numbering, so they stay gold and are not read as text. Kickers and footnote markers use gold-ink (#7E5F0B, 5.9:1). The focus ring is gold-ink on white surfaces and gold on navy surfaces (masthead, footer, newsletter block). Links inside the navy newsletter block are gold. The masthead's gold Newsletter button carries ink text (the first Lighthouse probe caught it inheriting the masthead's white link color, 2.2:1). The logo link has no aria-label; its name is its visible text, with the superscript 1 hidden from assistive technology. **OWNER:** confirm.

25. **Sample content.** Six sample pages (`site/src/content/samples/`) stand in for the templates with no real page yet: pillar, quick answer, place review, data page, comparison and cross-school guide. Titles start with "Sample", every paragraph says it is sample content, sources point at example.org and are labeled "not real", and the styleguide's sample byline reads "Sample Author" / "Sample Reviewer". They render only under `/styleguide/` (noindex) and feed the component gallery at `/styleguide/`.

26. **Place categories.** site.config `placeCategories` defines the standard fact fields for `dorm`, `apartment` and `dining_hall` as a starting set; a place page must supply every field of its category or the build fails. **OWNER:** confirm the field lists per category.

27. **Schedules.** Data pages carry `data.updated` and a methodology section; nothing refreshes on a schedule (repository rule: Ajay starts every step).

28. **Production switch and domain.** `SITE_PRODUCTION=1` removes noindex, allows crawling and fills the sitemap; without it every page is noindex and robots.txt disallows all, like the Jinja preview. site.config `url` defaults to `https://www.footnotedaily.com`, a placeholder (config/monetization.yml's domain is empty). **OWNER:** the real domain.

29. **Lighthouse and screenshots were run against a production-flag build** (`SITE_PRODUCTION=1 npm run build`) served from `dist/` by the local static server, which compresses text with Brotli and sends long-lived cache headers for assets the way Netlify does, so the SEO category measures the real pages rather than the preview's noindex tag and transfer sizes match a deployment. Lighthouse's own mobile emulation and simulated throttling were left at their defaults. Results and the Chrome version are in `reports/lighthouse/README.md`; screenshots in `reports/templates/README.md`. Lazy-loaded images are scrolled into view before each full-page capture.

30. **Touch targets.** Controls are at least 44px tall: masthead buttons, nav and sub-nav links, search and newsletter inputs and buttons, pagination, audience links, table sort buttons. Text links inside lists and prose (breadcrumbs, guide lists, sources, footer columns) keep their text height with a few pixels of padding; stretching every list link to 44px would double the length of the hubs and the footer. Lighthouse's tap-target audit passes on every template.

31. **Homepage H1.** The spec bans a hero and names the front-page lead card as the first element, so the homepage H1 is the site name and tagline, visually hidden, and the lead card's headline is an H2. Every other page has a visible H1.

32. **App preview config.** A "footnote-astro-dist" entry was added to `/Users/ajaysharma/Ads/.claude/launch.json` (outside the repository) so the desktop app's preview pane can open the built site.

33. **Deployed on Ajay's instruction (2026-11-08, in chat: "push all of this to the main netlify site", then "all of this should be merged with all of the work I'm doing").** Two Netlify projects exist under the account: `campus-ledger-preview` (where `scripts/deploy_netlify.sh` and `publish.sh` deployed the Jinja build; last pipeline deploy minutes earlier) and `footnote-daily` (the project the repo is linked to, named for the publication, last deployed 2026-11-06). The deploy is a noindex preview like the current site (no `SITE_PRODUCTION`): noindex meta, `Disallow: /`, plus the `X-Robots-Tag: noindex` header that `netlify.toml` adds. 35. **The pipeline now deploys the Astro site ("merged").** `scripts/deploy_netlify.sh` builds `site/` (`npm run build`, so a failed check stops the deploy) and deploys `site/dist` to footnote-daily; `CAMPUS_DEPLOY_LEGACY=1` restores the old deploy of `build/site` to campus-ledger-preview; `CAMPUS_ENVIRONMENT=production` with `CAMPUS_LIVE_DOMAIN` turns on the production build (indexable, robots from `config/crawlers.yml`, IndexNow key served) as the old script's comment already promised. `scripts/v2/publish.sh` keeps rendering the Jinja build for lint and local preview, and now passes `--site site/dist` to `indexnow.py` so IndexNow reads the deployed sitemap (an empty one on a preview, as before). The Astro `robots.txt` and `/<key>.txt` follow `config/crawlers.yml` on production builds, so the catch-up session's crawler policy carries over. Both files were replaced atomically because the pipeline may call them at any moment. One line was added to `CLAUDE.md`'s layout section so it keeps describing what runs. The old project campus-ledger-preview.netlify.app keeps its last Jinja deploy and is no longer updated.

36. **Git.** Every session commits to the same `main` in this checkout and pushes to GitHub; the site commits were pushed to `origin/main` as fast-forwards (no force), which is the merge Ajay asked for. The other session's commit c4730f5 had already swept the first batch of `reports/templates/*.png` into its own commit; the site commits update those files.

37. **Reader feedback form (added on Ajay's instruction after the deploy).** `FeedbackBox` ends every article template (pillar, quick answer, place, data, comparison, cross-school) with the same Netlify form the Jinja renderer used: name `answered`, fields `answered` (yes or no), `need` (free text, 600 characters), `page` (the path), honeypot `bot-field`, posting to `/thanks/`, which is `content/pages/thanks.md` rendered as a noindex trust page. No name or contact field. Without script the textarea and its Send button are visible; `public/site.js` turns them into a "No, I still need…" button that reveals them. Styled as a hairline block with a Newsreader italic question, not the old tinted box. Not on hubs, trust pages, search or the 404. The footnote-daily Netlify project had form detection off (`processing_settings.ignore_html_forms: true`, Netlify's default for newer projects), so the form was in the HTML but not registered; on Ajay's instruction it was enabled through the API and the site redeployed, and Netlify now lists the form `answered` with the fields `page`, `bot-field` and `need`. Netlify registers input and textarea fields only, not the submit buttons' `answered` value, so the No path requires text and the Yes button skips validation: an empty `need` is a yes, text is a no. The old campus-ledger-preview project had no registered forms, so the Jinja form never captured anything there.

38. **Plain Markdown loader.** Astro's glob loader runs every article through its Markdown pipeline (syntax highlighting, relative image resolution) although the templates never use that output; the first v3 article with a body photo (`![…](2.webp)`) failed the build with ImageNotFound. `src/lib/md-loader.ts` now reads frontmatter and body directly; validation and the renderer are unchanged. Dev mode does not hot-reload content edits with this loader (restart `astro dev`).

39. **Body photos.** As in `render_site.py` `place_images`: a body line `![alt](n.webp)` becomes a credited, lazy-loaded figure in place; a body reference to the lead photo is dropped (it is already under the title); frontmatter photos the body does not reference are placed before the second, third… H2, leftovers at the end; a file the build does not have is dropped rather than shown broken. `SITE_INCLUDE_UNPUBLISHED=1` renders every article for template review (the queue gate stays on otherwise).
